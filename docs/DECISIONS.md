# DECISIONS — Тут Бензин

Формат записи: дата, решение, почему, что отвергли.

## 2026-07-09 — Отдельное приложение, не общий код с platform
Тут Бензин живёт в `apps/polnyybak` со своей БД, деплоем и дизайн-системой.
Причина: противоположные требования (анонимный массовый B2C vs формальный
B2B-пилот). Отвергли: общие пакеты/монолит — тянули бы оба продукта в
компромисс.

## 2026-07-09 — Статус станции вычисляется из потока меток
Нет отдельного поля «текущий статус» у станции. Источник правды — последние
анонимные метки (`Mark`); статус и уверенность вычисляются на чтении.
Причина: не дублируем факт, история станции получается бесплатно.
Отвергли: денормализованное поле статуса — рассинхрон и лишние апдейты.

## 2026-07-09 — Анонимность через deviceId в localStorage
Никакой регистрации. `deviceId` — случайный токен на устройстве, нужен
только для защиты от накрутки повторными кликами. «Следить» за станциями —
тоже localStorage.

## 2026-07-09 — Стек: Next.js 16 + MapLibre GL + Prisma/Postgres + Tailwind 4
MapLibre — бесплатные тайлы/открытый стек, без привязки к Google/Yandex SDK.
Станции импортируются из OSM (`source: osm`), можно добавлять вручную.

## 2026-07-09 — Никаких новых технологий без записи здесь
Без Redis, очередей, микросервисов, CQRS, Event Sourcing. Один Next.js,
одна Postgres. Усложнение — только когда упрёмся в реальный предел.

## 2026-07-10 — Handbook: продуктовая документация отделена от технической
`handbook/` — как выглядит и работает продукт (WHY, PRODUCT, PRINCIPLES,
ANTI_FEATURES, USER_JOURNEYS, STRUCTURE, DESIGN, COPY, VISION).

Сценарии из USER_JOURNEYS.md — приёмочные тесты продукта: удлинение
сценария = регрессия. Тексты интерфейса живут в COPY.md, не в коде.

## 2026-07-10 — Мораторий на новые документы

## 2026-07-11 — Все АЗС из OSM, метки — демо-слой поверх
Станции импортируются из OpenStreetMap (scripts/import-osm.ts, зеркало
Overpass от Mail.ru — основной overpass-api.de недоступен по TLS).
2352 АЗС в 10 городах, upsert по osmId. Демо-метки (~60% станций,
распределение по тяжести региона) — временный слой до реального трафика;
prisma/seed.ts больше НЕ создаёт станций.

## 2026-07-11 — Карта: GeoJSON-кластеризация вместо DOM-маркеров
Тысячи станций → source cluster:true + circle-слои (цвет из свойства),
клик по кластеру раскрывает зумом, невидимый hit-слой 20px для тапов.
Слои добавляются по style.load (не 'load' — тот ждёт все тайлы и виснет
на медленной сети). Шапка карты pointer-events-none: пустые зоны
пропускают клики к карте (боевой баг: полоса фильтров съедала клики).
Живость: опрос /api/stations раз в 60 сек; история — /api/history.

## 2026-07-11 — PWA-установка: свои иконки, умный мастер по платформам
Манифест через app/manifest.ts (standalone, start_url /map). Иконки
генерируются scripts/gen-icons.mjs — PNG-энкодер на чистом node:zlib,
без зависимостей (принцип «никаких новых технологий»). Правила показа
(решение владельца): системный prompt где доступен; iOS — инструкция
только в Safari, во встроенных браузерах — «откройте в Safari»;
авто-показ после вовлечения (2 карточки / метка / 45 сек), снуз 30 дней,
установленным — никогда; кнопка в шапке до установки.

## 2026-07-11 — Ребрендинг: «Полный Бак» → «Тут Бензин» (решение владельца)
Переименование до появления пользователей. Причины: название = ответ на
поисковый запрос («тут есть бензин»), совпадает с каналами @tyt_benzin /
@tyt_ben3in, конкретное действие вместо абстрактного бренда, сильные
рекламные связки («Нет бензина? — Тут Бензин»). Заменено во всех UI-строках,
манифесте PWA, handbook и docs. Слово «карта» убрано из интерфейсных CTA:
«Показать, где есть бензин» вместо «Открыть карту» (в SEO-title «карта»
осталась намеренно — под запросы). Папка apps/polnyybak и slug'и не
переименованы — это техническая номенклатура, не бренд.

## 2026-07-11 — Бренд закреплён; ЧТО/КАК; ритм 80/20
Бренд финализирован: «Тут Бензин», домен tytbenzin.ru, @tyt_benzin,
каналы MAX — всё одинаково. Логотип — пиктограмма (геометка с каплей
топлива), одна и та же иконка для favicon/PWA/сторов, генерируется
scripts/gen-icons.mjs. Правило дизайна: ГдеБЕНЗ определяет ЧТО (набор
функций), Apple/Linear/Arc/Tesla определяют КАК (внешний вид). Ритм:
80% функциональность / 20% постоянная полировка в каждой итерации —
вместо большого редизайна в конце. Поиск-плейсхолдер — «Где есть
бензин?» (пользователь хочет ответ, не карту).

## 2026-07-12 — Цвет на карте = «сюда можно ехать»
Визуальная иерархия пинов (ревью владельца): станции с топливом
(есть/мало/очередь) — крупные цветные с белой обводкой; «нет бензина» —
серые поменьше; «нет данных»/закрытые — почти прозрачный мелкий фон.
Карта читается за секунду: цветное = варианты, серое = мимо. Фильтры
по-прежнему приглушают неподходящее до 0.15.

## 2026-07-12 — Процесс: декомпозиция конкурента, Design Score, PRODUCT REVIEW
Не копировать ГдеБЕНЗ — декомпозировать (что оставить/убрать/улучшить по
каждому экрану). Design Score по 6 осям, экран не закончен при WOW < 9
или Понятность < 9; 10 проверок экрана; блок PRODUCT REVIEW после каждого
экрана до следующего кода. Вдохновение по областям: Apple — простота,
Linear — типографика, Arc — микроанимации, Flighty — доверие, Uber —
карточки; Awwwards — только hero/лендинг, не рабочий интерфейс.

## 2026-07-12 — Сервис принятия решения: режим ответа и TTA
Главное правило проекта (владелец): пользователь открывает сервис не
смотреть карту, а принять решение «ехать сюда или нет». Второй KPI —
TTA (Time To Answer) < 5 сек. Реализация: по умолчанию на карте ТОЛЬКО
станции с топливом (есть/мало/очередь), пустые и безмолвные скрыты —
тумблер «Все АЗС» возвращает их (фильтры «Нет»/«Закрыта» включают показ
автоматически); кнопка-ответ внизу: «Есть бензин: N АЗС — показать» →
список ближайших. Красного на карте нет. История в карточке упрощена:
время + факт, без псевдонимов (владелец: имена не несут пользы —
отменяет решение от 2026-07-12 об именах; поле name в API оставлено).

## 2026-07-12 — Думаем как Waze: ответ — продукт, карта — инструмент
Решения владельца: экран-ответ при входе на /map («🟢 Есть бензин рядом ·
441 заправка · обновлено N мин назад · [Показать]»), карта вторична;
«Поехать» — главное зелёное действие карточки (выбор: Яндекс Карты,
2ГИС, Google Maps, Apple Maps), «Подтвердить» — вторичное; язык водителя:
«заправка» вместо «АЗС» во всём UI (АЗС только в SEO), «Проверили N
водителей» вместо «Подтверждено», очередь — сначала вывод, потом цифра
(«Небольшая · ≈5 минут», «Свободно»). Правило в AGENTS: «Ответ всегда
выше данных». Позиционирование: сервис, который за несколько секунд
помогает принять решение, где заправиться; пользователь покупает
уверенность, что не поедет впустую.

## 2026-07-12 — Sprint 2 «Лучше ГдеБЕНЗ»: Сейчас-режим, Яндекс/2ГИС, надёжность звёздами
Экран-ответ стал режимом «Сейчас»: количество живых заправок + «Самая
близкая — 1.0 км · Кремлёвская АЗС» + зелёная «Поехать» (карта — по
кнопке «Посмотреть на карте»). Маршруты: ТОЛЬКО Яндекс Карты (по
умолчанию, без модалки) и 2ГИС (запасная ссылка) — Google/Apple Maps
убраны (решение владельца). Карточка отвечает в порядке решения:
статус → топливо → очередь → проверяли → проверили → надёжность →
Поехать. Надёжность — звёзды + слова («Очень надёжно»), проценты убраны.
«Рядом с вами»: нумерация, метры, «Поехать» на каждой строке. Кластеры
«стеклянные» (белые полупрозрачные, зелёная обводка, тёмное число) —
живые точки главнее. Правило AGENTS: «какое решение принимает человек
на этом экране» (нет ответа — экран не нужен).

## 2026-07-13 — Отметка 2.0: уточнение топлива (вопрос владельца)
Проблема: метка «Нет топлива» не говорила, КАКОГО топлива нет (95 может
быть, а 92 нет). Решение: тап статуса остаётся мгновенным (1 тап, метка
сохранена), после — необязательное уточнение прямо в «Спасибо»: «Какого
топлива нет?» / «Какое топливо есть?» чипы + очередь → PATCH /api/marks
дополняет СВОЮ метку (deviceId + возраст < 10 мин), новую не создаёт.
История говорит «Закончился: 95». Частичное «нет»: OUT с указанным
топливом при живом другом топливе даёт станции статус «Мало» (жёлтый),
а не «Нет» — детали по видам в строках карточки. Dedup POST возвращает
markId последней метки — уточнение работает и при повторном тапе.

## 2026-07-13 — Отметка 3.0: марки вместо общего статуса
Модель: fuelTypes = какие марки ЕСТЬ, fuelsOut = какие ЗАКОНЧИЛИСЬ,
limitInfo = лимит отпуска, очередь в минутах (5 корзин + legacy OVER_20).
Форма: «Что происходит?» (без «Нет топлива» — незачёкнутые известные
марки автоматически дают «Нет») → «Какие марки сейчас есть?» чекбоксы
(+Газ) → «Сколько ждать?» → «Лимит отпуска» → превью «Так это увидят
другие» + прогресс «N из 4». Ничего не выбрано из марок = станция OUT.
Быстрые кнопки и уточнение в «Спасибо» сохранены (1-тап путь жив).
История: «Есть: 92, ДТ · Нет: 95». Мигрировано 1292 старых OUT-меток
(fuelTypes → fuelsOut). Оплата и цена — сознательно в BACKLOG (правило
Джобса: меньше полей — выше отправляемость). Урок: после prisma db push
перезапускать dev-сервер — иначе старый клиент в памяти даёт 500.

## 2026-07-13 — Мастер установки с выбором браузера; фирменные пины

## 2026-07-13 — Слой «данные устарели» (3–24 ч) и фикс мастера установки
Вместо бинарного TTL — три уровня свежести: <3 ч — яркий пин, полная
надёжность; 3–24 ч — статус ВИДЕН, но пин бледный (opacity 0.45, меньше,
без капли), в карточке «⚠ Данные устарели — проверьте и подтвердите»,
надёжность капится 2 звёздами «Данные устарели»; >24 ч — «нет данных».
Карта выглядит живой (сид: 45% свежих / 35% устаревших / 20% старых),
честность сохранена. Фикс мастера установки: чипы браузеров показываются
ВСЕГДА (раньше системный prompt прятал их — потому «не переключалось»);
кнопка «Установить в один тап» — сверху, инструкции — ниже.

## 2026-07-13 — Деплой на reg.ru: Docker Compose + Caddy
Прод-стек (запрос владельца «деплой на регру»): облачный сервер reg.ru
(Ubuntu 24.04, от 2 vCPU/2 ГБ) + Docker Compose: postgres:16 + приложение
(Next standalone, свой Dockerfile) + Caddy (автоматический HTTPS от
Let's Encrypt при заданном DOMAIN). Docker — деплой-инфраструктура, не
усложнение рантайма (рантайм прежний: один Next, одна Postgres).
outputFileTracingRoot = __dirname — иначе standalone уезжает в структуру
монорепо. Сервисы-инструменты в compose: migrate (prisma db push),
import (OSM). Демо-метки на прод не сеются (см. DEPLOY.md). Инструкция —
docs/DEPLOY.md (утверждён владельцем: ускоряет решения). Прод-сборка
проверена локально: standalone сервер отдаёт /, /map, /api/stations.

## 2026-07-25 — Цена топлива в отметке: модель на каждую марку
Цену водитель вводит вместе с отметкой; она остаётся в истории АЗС,
чтобы было видно, где дешевле. Модель — не одно поле на станцию,
а объект на КАЖДУЮ марку: значение, собственное время обновления,
число подтверждений (считается по разным устройствам, подтверждена
от 2), свежесть (до 24 ч — свежая, 24–48 ч — стареющая, старше 48 ч —
не показываем) и флаг `needsConfirm` при отклонении свыше 15% от медианы
остальных. Цены не берутся из демо-слоя (`source='seed'`) и не хранятся
для статусов OUT/CLOSED; PATCH отметки удаляет цену марки, которую убрали
из состава. Тесты: `npm run test:price` (8 кейсов логики) и
`npm run test:price:db` (интеграционный прогон PATCH).

## 2026-08-04 — Серверные оффлайн-конверсии в Метрику по yclid
Клиентский тег Метрики до согласия отключён, поэтому Директ видел ноль
конверсий и оптимизировал дешёвые клики. Решение: `mark_completed`
берётся из своей БД, по `AnalyticsSession.yclid` находится клик Директа,
конверсия грузится в Метрику по API (счётчик 110795596, цель 585593829),
дедуп — таблица `OfflineConversion`. Обходится ТЕГ, а не согласие:
источник — внутренняя аналитика, которая без «Принимаю» не пишется.
Передача описана в политике конфиденциальности (редакция 20.08.2026).
Запуск: `npm run conversions` / `docker compose run --rm conversions`,
ночной крон.
